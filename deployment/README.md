# Render: один сервис WindPilot

Страница отдаётся существующим FastAPI `FileResponse` на `/`; отдельного фронтенд-сервиса, CORS или CDN нет. Перевод на `StaticFiles` не требуется для одного HTML. `render.yaml` задаёт **Free**, Python 3.11, один Uvicorn worker и `$PORT`.

## Публикация

1. В Render выбрать **New → Blueprint**, подключить репозиторий `BAITC-Hacks/hack-16b87636-entropy`, ветку с этими изменениями и файл `render.yaml`.
2. Проверить, что выбран план **Free**, и создать сервис. Модель не переобучается при сборке.
3. Дождаться **Live**, скопировать фактический URL `https://…onrender.com` из карточки сервиса. Имя URL заранее не гарантируется.

Вариант без Blueprint: **New → Web Service → Python**, build `pip install -r requirements.txt && python scripts/restore_runtime.py`, start `python -m uvicorn windpilot.api:app --host 0.0.0.0 --port $PORT --workers 1`, health `/health`, переменные из `render.yaml`.

Также сервис можно создать через подключённый Render MCP с теми же параметрами. Публичный адрес и состояние деплоя нужно проверять по фактическому сервису Render; наличие локального пакета само по себе не означает, что сайт опубликован.

## Переносимость и данные

`runtime.zip` — явный список runtime-файлов: две прежние модели, январские метрики, подготовленная часовая история для бейзлайна, кэш Open-Meteo и 58 сохранённых расчётов дашборда. Список с SHA-256 каждого файла — `manifest.json`. Архив входит в репозиторий, несмотря на исключённые рабочие папки `artifacts/` и `data/`. Скрипт восстановления проверяет контрольные суммы и не перезаписывает изменённые локальные данные. Никаких путей `D:/Downloads` для запуска сайта не требуется.

Исходные CSV, `.env`, токены, виртуальное окружение и новые пользовательские живые запросы в архив не включаются. Ключ для Open-Meteo не нужен. Модель и самодостаточный HTML сохраняются без изменения численных прогнозов.

Пересобрать пакет после осознанного обновления модели/архива:

```powershell
.\.venv\Scripts\python.exe scripts/package_runtime.py
```

Восстановить в чистом checkout:

```sh
python scripts/restore_runtime.py
```

На Free нет persistent disk; новые расчёты/логи и пополнения кэша могут теряться при перезапуске или деплое. Базовые артефакты восстанавливаются из репозитория. Сервис засыпает после простоя, поэтому первое открытие может занять время. Во время сна автоматическая проверка погоды также не выполняется. Пока процесс работает, встроенный планировщик проверяет текущую погоду каждые 900 секунд после завершения предыдущего цикла; состояние доступно в `/agent/status`. См. [ограничения Render Free](https://render.com/docs/free). Этот режим подходит для демонстрации; долговременное хранение живых запусков и непрерывная работа не обещаются.

## Проверка после появления публичной ссылки

Из другого устройства или чистой браузерной сессии открыть фактический URL:

- 31.01 и 28.02, 24/48 часов, установки 1/2/обзор: корректная шкала 0–100%, соответствующая модели 0–1; даты позже 28.02 недоступны, подсказка видна.
- «Посмотреть шаги агента»: реальные шаги/кэш и версия модели, без LLM-чата.
- «По часам» и «Подобрать период»: таблица соответствует графику, порог и длительность меняют результат; метрики обучения не показаны в бизнес-интерфейсе.
- CSV: выбранные турбины и горизонт, 8 полей результата.
- Тёмная/светлая тема: читаемые графики, выбор сохраняется после перезагрузки.
- «Живой прогноз»: текущая дата, реальный Open-Meteo, демо-оговорка, нет выдуманного времени выпуска и актуального бейзлайна; возврат в историю работает.
- При недоступной погоде ошибка показывается честно; при недоступном сервере архивный просмотр помечен автономным.

HTTP-проверка из другого окружения: `python scripts/check_public_service.py https://ФАКТИЧЕСКИЙ-АДРЕС.onrender.com`. Она проверяет API, включая настоящий live-запрос, но не заменяет визуальный браузерный сценарий.
